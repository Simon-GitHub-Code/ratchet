# Adoption provisions what the first slice needs, and rehearses it

A dogfood run on 2026-11-13 played a non-engineer building a read-later web app from an empty directory (TypeScript on pnpm, hono, oxlint). `/ratchet:adopt` took 19.5 minutes and $7.77, and every gate was green. The first `/ratchet:feature` then stopped eight minutes in. Its spec role needed three edits to guard paths, and the pipeline cannot make those unattended. It needed the `jsx` keys of `tsconfig.json`, which adoption had written and then removed because the dead-code gate called `hono` unlisted. It needed the lint override that let the one settings module read the environment, which the `AGENTS.md` adoption wrote promised and no config held. It needed the test runner and a property-testing library in the lockfile, because adoption had left them to `code:source`. The spec role filed a dispute and sent the owner to an interactive session. After 91 minutes there was no working app, and the app built later had no way to start it: `boot` was `"none"`, as adopt step 9 said to set it. Nothing recorded a change-size ceiling either, so the gate passed every size.

ADR 0028 asks each safeguard when its trigger fires, so the first commit is the owner's idea and not a skeleton. That stands. These four were not safeguards. They were what the first feature's own roles needed before they could start, and the first feature is the change least able to supply them.

## Decision

**The tests are provisioned, not asked.** Adoption chooses the test runner, and a property-testing library where the runner has none, installs both, configures them (the test and critique directories, every core) and locks them, on every repository. The `unit, property and fitness tests` row stays `later: code:source`. A bound collection gate is red with nothing to run (ADR 0020), and the owner decided on 2026-11-11 that `code:source` owes its rows at once. The binding's new `## Tests` section names the frameworks and directories, which is where the spec role and the critic already look. The `justfile`'s `test_runner` holds the command that runs the test files named after it. `just test-files <file>...` runs it for the roles while no gate does. When the first module arrives, `/ratchet:safeguard` binds the row by writing `{{test_runner}}` with its shard flags into `test`, and installs nothing. The Tool cell carries no tool before then: `later: <trigger>` is one whole cell, read as data by the triggers gate (ADR 0028), and a second grammar after it would leave the row never owed.

**A stack rule describes the tree as adoption leaves it.** Every config a rule in `AGENTS.md` or the binding names is written at adoption: an exemption for the one module allowed something, a directory a tool includes, a compiler key a declared type needs. No rule leaves a config to "the change that brings" something, since that change belongs to the unattended pipeline and a config is a guard path. A key a declared type needs is never removed to quiet a gate. Adoption installs the package the key names, has the tool's setup use it, or gives the gate its narrowest exception. Prose alone cannot hold this, so step 12 rehearses the first slice. In a worktree of the adoption's commit, adoption adds the runtime packages slice one needs and writes the smallest real instance of each kind of code it brings, in a form its Triggers row counts. It also writes the entry file `boot` runs, an instance of each rule that allows something in one place, and a unit test and a property test. Then it runs `check`, the tests and the boot. The rehearsal passes when nothing is red but `triggers`, and when the guard diff against the adoption lists only the dependency manifest, its lockfile and their snapshots. Any other edit is a config the adoption owes. Nothing of the rehearsal is committed. The rehearsal would have failed on all three of the dogfood's blocks: the `.tsx` page on the missing `jsx` keys, the settings module on the missing override, and the tests on the missing runner. Its first real run found two more: SQL migrations the build did not copy, and a database file `.gitignore` did not ignore. On that adoption, the dogfood's first ticket changed no guard path but the dependency manifest, its lockfile and their snapshots.

**`boot` is filled for every type that boots.** `boot` holds the command the stack's conventions imply for the entry file `AGENTS.md` names, written before that file exists. `ready` holds the URL it answers on, or `"none"` for a `cli`, `job` or `app`, whose smoke runs `boot` to its exit. A `library` sets both to `"none"`. On an empty repository nothing runs `boot`, because every row that boots is still `later:`. Its first run is the rehearsal, and its first gate is the smoke `/ratchet:safeguard` binds with the first entry point. `just start` runs it for a person and prints where to open it, and the hand-over says so.

**The first change-size ceiling is the method's: 40 files and 1500 lines.** The adopt template ships `[ceilings.change]` live. ADR 0010 holds that a first ceiling never comes from what an empty tree measures, since a young project's numbers turn the first feature's normal growth into an ADR. A change ceiling has nothing to measure at all, because the adoption's commits are exempt. So its first value is the method's number, and it is set by the slice the method expects. The pipeline's spec stage stops a ticket as too large at two thirds of the ceiling, and the critic's tests add about two fifths once the project is `depended-on`. The dogfood's first ticket measured 20 files and 683 counted lines. That is under the two-thirds stop of 1500 lines and 40 files (1000 lines, 26 files), and with the critic's share, about 1140 lines and 23 files, it is under the ceiling. The round pair below it, 1000 lines, would stop that ticket at the spec. A ceiling only falls, so a loose first value costs nothing to lower. A tight one costs the first feature an ADR. This closes the bound ADR 0030 left open: the change that brings the first instances of a kind of code is free for that kind, and this ceiling bounds it from the first day.

## Refutation criterion

This is wrong if the first feature built by the pipeline on either of the next two adoptions changes a guard path other than the dependency manifest, its lockfile and their snapshots, while that adoption's rehearsal passed. The rehearsal then does not stand in for the slice, and a script that writes and judges it (`rehearse.py`) takes its place. It is wrong if `/ratchet:safeguard`, binding the test row, installs a package. It is wrong if the rehearsal takes more than a quarter of an adoption of an empty repository. The first rerun with this decision spent 8 of its 43 minutes on it, on a machine at a load average near 60. The ceiling is wrong if a ticket that is one vertical slice stops as too large under it. It is also wrong if none of a repository's first ten changes reaches a third of it, because a ceiling nothing approaches bounds nothing, and it comes down.

## Considered options

- **Ask the test row at adoption.** Rejected. It is red on an empty tree (ADR 0020), and it reopens the owner's decision that `code:source` owes its rows at once.
- **Name the ready tool in the Tool cell** (`later: code:source (vitest)`). Rejected. Conformance reads the whole cell as the trigger and is red on it, and the triggers gate would never find the row owed.
- **Keep an example test in the tree to show the tools work.** Rejected. It tests nothing, keeps the suite's collection from ever being empty, and is the skeleton ADR 0028 removed.
- **A static check that each promised config file exists.** Rejected. The dogfood's lint config existed, and the override it promised did not. Only running the gates over an instance shows a key is there.
- **Leave `boot` at `"none"` until the first entry point.** Rejected. The owner could not start what the pipeline built, and the first safeguard would guess the command after the code had chosen its shape.
- **Measure the change ceiling after the first feature.** Rejected for ADR 0010's reasons: a window with no ceiling, which the free first change cannot have, and a step someone must remember.
